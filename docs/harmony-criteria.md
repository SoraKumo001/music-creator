# 和声進行の判定基準（Phase 0）

この文書は「良い進行 / 破綻した進行」の判定を固定する。実装（`theory/validate.ts` 以降）とテストはこの基準に従う。
基準を変えるときは、先にこの文書とテストを直す。

---

## 1. 判定の 3 段階

| 重大度 | 意味 | 生成パイプラインでの扱い |
|---|---|---|
| `error` | 音楽として成立しない、または解釈できない | LLM に差し戻して再生成（`maxAttempts` 後は補正して続行） |
| `warn` | 不自然だが直せる | 決定的に補正する。補正内容はログに残す |
| `info` | 意図的な表現として許容する | 記録のみ。生成は止めない |

**原則**: `error` は「解析不能」と「調の不整合」だけに絞る。進行の好みは `warn` / `info` に留め、LLM の表現を殺さない。

---

## 2. Issue コード

| コード | 重大度 | 条件 | 補正 |
|---|---|---|---|
| `PARSE_ERROR` | error | コード記号が解釈できない | 再生成 |
| `KEY_MISMATCH` | error | 宣言キーと調号が合わない（例: `C major` なのに主和音が `Cm`） | 再生成 |
| `NO_TONIC` | warn | トニック和音が一度も出ない | 最初の小節をトニックへ |
| `NO_CADENCE` | warn | 最後の 2 小節に終止がない | `ii–V` または `V–I` を挿入 |
| `WEAK_ENDING` | warn | 最終和音がトニックでない | 直前を `V`、最終を `I` に置換 |
| `RETROGRESSION` | warn | `D → S` の逆行（例 `V → IV`、`V → ii`） | 経過和音を挟むか順序を入れ替える |
| `HARMONIC_RHYTHM` | info | 拍頭以外でのコードチェンジ、1 拍未満の和音、2 小節超の和音 | 拍グリッドへスナップ、短い和音は統合 |
| `TOO_FEW_CHORDS` | warn | 4 小節あたり 2 和音未満 | 和音を追加 |
| `TOO_MANY_CHORDS` | warn | 4 小節あたり 8 和音超 | 和音を統合 |
| `SECTION_CADENCE` | warn | セクション境界の直前小節に終止がない | 境界前に `V` を挿入 |
| `CHROMATIC_UNEXPLAINED` | info | 借用でも二次ドミナントでもない調外和音 | 記録のみ |
| `LOOP_LEAD_IN` | warn | ループ用で、最終和音が導音でもトニックでもない | 最終和音を `V7` に |
| `LOOP_TARGET` | info | ループ用で、最初の和音がトニックでない | 記録のみ |

## 3. 機能の定義

| 機能 | 長調 | 短調 |
|---|---|---|
| T（トニック） | I, iii, vi | i, III, VI |
| S（サブドミナント） | ii, IV | ii°, iv, VI |
| D（ドミナント） | V, vii° | V, v, VII, vii° |

- **基本進行**: `T → S → D → T`。`S → D` は可、`D → S` は逆行。
- 逆行は `warn`。ポップスでは `I–V–IV` のように意図的に使われるため、`error` にはしない。
- 二次ドミナント（`V7/x`）は機能 `D`、借用和音は元の度数から機能を決める。
- 二次ドミナントが対象へ解決する場合（`V7/IV → IV`）は逆行にしない。

### 表記の約束

- 短調のダイアトニックは**自然短調を基準**に `i, ii°, III, iv, v, VI, VII` と書く。長調基準の `bVI` などは使わない（A 短調の F は `VI`）。
- 和声短調の `V` / `vii°` は調内として受理する（表記は `V`, `vii°`）。
- セブンスの調内判定は「ダイアトニックな 7th の種類」で行う。したがって C 長調の `C7` は `Imaj7` ではないため `V7/IV` と解釈する（ブルースの I7 はこの扱い）。
- 二次ドミナントより**借用を優先**する。A 短調の `D` は `V/v` ではなく、平行長調からの `IV`。

## 4. カデンツの定義

| 種類 | 定義 |
|---|---|
| `PAC`（完全終止） | `V → I`。両方とも基本形（転回形でない） |
| `IAC`（不完全終止） | `V → I` だが、どちらかが転回形 |
| `HC`（半終止） | 進行が `V` で終わる |
| `PC`（変格終止） | `IV → I` |
| `DC`（偽終止） | `V → vi`（短調では `V → VI`） |
| `none` | 上記以外 |

メロディを持たない段階では、PAC / IAC の区別は転回形だけで近似する（ソプラノの終止音は見ない）。この近似は実装コメントに明記する。

- 最後の和音が同じ記号で伸ばされている場合（`C–C`）は、直前の「変化」を終止として見る。
- `I7` はブルースのトニックとして扱う（`G7 → C7` を `PAC` と判定する）。

---

## 5. 和声リズム

- 1 小節あたり **1〜2 和音**を標準とする（4/4）。
- コードチェンジは**拍頭**（整数拍）に置く。裏拍・半拍は `info`。
- 1 和音が 2 小節を超える場合は `info`（意図的な持続として許容）。
- セクションの最後の小節は、次のセクションへ向かうカデンツを優先する。

---

## 6. 借用和音・二次ドミナントの許容

| 種類 | 表記 | 扱い |
|---|---|---|
| 二次ドミナント | `V7/V`, `V7/ii` など | 許容。機能は `D` |
| 裏コード | `bII7`（`subV7`） | 許容。機能は `D` |
| ナポリ | `bII` | 許容。機能は `S` |
| 平行短調からの借用 | `iv`, `bVI`, `bVII`, `bIII`, `v` | 許容。`info` |
| 平行長調からの借用（短調） | `I`（ピカルディの3度）など | 許容。`info` |
| ドリアンからの借用（短調のIV） | `IV` | 許容。`info` |
| ミクソリディアンからの借用 | `IV7`（ブルースの色） | 許容。`info` |
| 上記以外の調外和音 | — | `CHROMATIC_UNEXPLAINED`（`info`） |

借用・二次ドミナントは「説明できる調外」であり、`error` にしない。

---

## 7. 受け入れ基準（Phase 1〜3 完了時点）

1. 任意のコード記号が `analyzeChord(symbol, key)` でローマ数字・度数・機能に変換できる
2. 長調・短調のダイアトニック和音が 12 キーすべてで往復（実現 → 解析）する
3. 転回形・二次ドミナント・裏コード・ナポリ・借用和音が表駆動テストで固定されている
4. カデンツ検出が `PAC / IAC / HC / PC / DC / none` を返す
5. 進行カードが全件、指定キーで実現でき、コードのルートと品質が一致する
6. `validatePlan` が §2 の Issue コードを返し、`repairPlan` が warn を決定的に補正する
7. `npm run typecheck` と `npm test` が成功する
